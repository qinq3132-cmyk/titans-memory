# V6 零训练改动 Benchmark 评估

> **日期**：2026-11-24
> **Checkpoint**：`checkpoints_v6/best.pt`（量化存储 + 写噪声，部署条件最完整版本）
> **性质**：纯评估，**零训练改动**——复用现有 checkpoint，不改任何权重
> **脚本**：`evaluate_benchmarks_v6.py`
> **输出**：`eval_benchmarks_v6/`（CSV + 汇总 + 图表，按 variant 子目录 + 合并根目录）

## 一、目的

此前的 8 组实验只用 BPC + Acc（enwik8 定长评估）一种指标形式。本组实验引入 Titans 原论文（NeurIPS 2025）使用的 benchmark 家族中**在 19.79M / enwik8 字符级规模下可零训练运行**的部分，回答三个此前未量化的问题：

1. **记忆模块的检索能力有多远？**（有效上下文长度）
2. **忆阻器读量化/读噪声是否损害检索能力？**（器件条件 vs 检索距离）
3. **超长流式输入下记忆是否退化？**（retention / drift 担忧）

## 二、Benchmark 设计

### 1a. 段落重复探针（passage repeat probe）★ 主指标

64 字符自然文本（val 区域，prose 启发式筛选）在上下文 depth（25%/50%/75%）处出现一次，序列末尾完整重复一次。对比两次出现的 BPC/Acc：

- `ΔBPC = 第一次 BPC − 第二次 BPC`（正值 = "见过"带来改善 = 纯记忆检索贡献）
- 关键口径：段落**后半段**（chars 32-63）超出 36-token 注意力窗口，其改善**只能来自 Neural Memory 跨段检索**
- 距离扫描：288 ~ 12192 字符（长度 512 → 16384 × 深度 25/50/75%）
- 此任务不需要模型学过任何指令格式，是纯 LM 场景下最干净的检索测试

### 1b. 随机 needle NIAH（对照）

16 个随机字母数字字符插入上下文，末尾重复前 8 字符，评分后 8 字符 completion（对应 RULER S-NIAH 的字符级适配）。

### 2. 流式超长上下文 BPC

enwik8 val 连续流（单次 forward，内部按 32-token 段滚动记忆）喂到 32K（= 训练长度 512 的 **64 倍**），按 512-char 窗口记录 BPC-位置曲线；`drift = 末窗 BPC − 首窗 BPC` 为漂移指标。

### 三种设备条件（与 v6 量化噪声评估完全一致）

| variant | 读路径 | 写路径 |
|---------|--------|--------|
| fp32_clean | 不量化不加噪 | 4-bit 量化存储 + 5% 写噪声 |
| quant_only | 4-bit 量化，无噪声 | 同上 |
| quant_noise | 4-bit 量化 + 5% 读噪声 | 同上 |

全部评测序列固定种子预生成，**跨 variant 完全一致**（公平对比）。

## 三、结果

### 3.1 段落重复探针：ΔBPC 按检索距离分桶

| 距离 (chars) | fp32_clean | quant_only | quant_noise |
|--------------|-----------|-----------|-------------|
| 0–500 | **+0.076** ± 0.074 | **+0.060** ± 0.079 | **+0.051** ± 0.074 |
| 500–1K | **+0.080** ± 0.090 | **+0.054** ± 0.059 | **+0.083** ± 0.082 |
| 1K–2K | −0.028 ± 0.042 | −0.042 ± 0.021 | −0.053 ± 0.031 |
| 2K–4K | +0.022 ± 0.010 | +0.033 ± 0.006 | +0.022 ± 0.021 |
| >4K | −0.057 ± 0.051 | −0.048 ± 0.037 | −0.030 ± 0.048 |

（均值 ± 标准差；每桶 n=2–6 个 (长度×深度) 配置，n=5 序列/配置）

**关键发现：三条曲线几乎重合。** 检索增益在 ~1K 字符内明确为正（+0.05~0.08 BPC，对应 ΔAcc +1.2~+4.7pp），~2K 后进入噪声区，>4K 消失（略负）。**且三种器件条件的有效检索距离没有差别**——读量化/读噪声不损害"能记住多远"，只影响整体精度幅度（此前测得的 ~4.5% 部署税）。

单配置最大检索增益：ΔBPC +0.183（quant_only，dist=97），ΔAcc +4.69pp（fp32/quant_only，dist≈1K）。

### 3.2 随机 needle NIAH：一致性负结果

全部 27 个配置（3 variant × 3 长度 × 3 深度）completion Acc 均值 **0.93%**（最大 4.17%，BPC ≈ 7.7-8.6 = 随机水平），且三个 variant 完全相同。

**解释**：19.79M / 100MB 字符级模型没有学到"随机字符串 induction"——记忆存储的是文本统计，而"见到 prompt → 从记忆中取出配对内容"这一检索行为从未在 enwik8 训练分布中出现。Titans 论文的 NIAH 成绩来自 170M-760M + 15-30B tokens（150-300 倍数据量）。**这是规模/数据的边界，不是架构或器件的缺陷**——记录为对照发现。

### 3.3 流式 32K：记忆巩固稳定

| variant | seq0 BPC / drift | seq1 BPC / drift |
|---------|------------------|------------------|
| fp32_clean | 1.3759 / **−0.079** | 1.4324 / +0.052 |
| quant_only | 1.3919 / **−0.164** | 1.4524 / +0.015 |
| quant_noise | 1.4091 / **−0.218** | 1.4563 / +0.008 |

drift 全部 ≤ +0.06（两条流显著为负 = 首窗预热后 BPC 反而变好）。**64 倍训练长度的连续流上，记忆巩固无位置退化**；读噪声条件（quant_noise）与干净条件行为一致。忆阻器 retention/drift 担忧在 32K 尺度上被架构吸收。

## 四、结论

1. **检索能力与器件条件解耦**：有效检索距离（~1K 字符内明确有效，>4K 消失）由记忆容量/训练决定，4-bit 读量化 + 5% 读噪声不改变"能记住多远"。结合此前 ~4.5% 部署税的结论：**忆阻器化的代价是精度幅度，不是记忆能力**。
2. **有效检索距离 ~1-2K 字符是当前规模的天花板**：受限于 19.79M 模型 + 100MB 训练数据 + 无检索行为监督。更大规模/数据或在训练中加入检索式任务（如合成 recall）可扩展——这是后续训练实验的方向。
3. **记忆巩固在 64 倍训练长度上稳定**：32K 流 drift ≈ 0，三条件一致。retention 风险（忆阻器漂移对应的数字域对应物）在 32K 尺度未显现。
4. **随机串检索是规模边界**（对照发现）：零训练条件下小模型不做 induction 式检索；NIAH 类指标在此规模需用段落重复探针替代。
5. **段落重复探针是本规模下 NIAH 的正确替代**：无需指令格式、可扫距离、增益可归因于记忆（后半段超出注意力窗口）。

## 五、限制与后续工作

1. **流式上限 32K**：64K/128K 流式因库的内存布局受限未跑——`store_memories` 将记忆初始权重按 chunk 数全量复制（`neural_memory.py` L659 `repeat_dict_values` + L749 vmap 全量展开），128K = 32768 chunks → 峰值 ~40GB。**修复方案**（数学等价、仅改内存布局）：vmap 按 chunk 分块循环（块内 repeat+量化+梯度，块间拼接），预计峰值降到 ~1-2GB。修复后需用 4096 单块路径与现有 CSV 做等价性验证，再补 64K/128K。
2. **统计功效**：每配置 n=5 序列、每距离桶 n=2-6 配置，passage 难度方差（±0.04-0.09）与桶间差异同量级——结论以"三 variant 曲线重合"为主要依据（配对比较消除 passage 难度混淆），距离衰减的精确形状需 n≥20 确认。
3. **检索无监督**：模型从未被训练去"检索"，探针测的是"顺带形成的能力"。后续可在训练中混入少量合成 recall 任务（MQAR 式），预期显著扩展有效距离——与忆阻器容量包络实验（bit/noise sweep × KV 对数）形成组合。
4. needle 探针保留为对照指标（`--skip-needle` 可关）。
